## Notes / decisions

- **Scope shipped: "native + live block counts".** Engine FFI gives rule count and filter list freshness (via the build-time meta JSON); extension gives block aggregates via native messaging + file in its sandbox container.
- **Stats source is the extension via `chrome.storage.local`, not the Rust engine.** Block events happen in the browser's network stack. The extension also persists to `Documents/mane-stats.json` so the unsandboxed container app can read them.
- **Container app is unsandboxed (`ENABLE_APP_SANDBOX = NO`).** App Groups would have been the clean cross-sandbox channel but they require a real development certificate (`security find-identity` shows none installed). Unsandboxed Mane reads the extension's sandbox container directly. When Abdulla signs in to Xcode the architecture migrates to App Group + `UserDefaults(suiteName:)` and Mane goes back to sandboxed.
- **Modern Safari Web Extensions don't have `SFSafariExtensionHandler.messageReceivedFromContainingApp`.** That's the pre-MV3 API. The replacement path is `runtime.sendNativeMessage` from JS to the extension's `NSExtensionRequestHandling.beginRequest`, with no equivalent app-to-extension dispatch surface, so we use a push-from-extension model rather than poll-from-app.
- **`getMatchedRules()` on Safari for static rulesets is an empirical unknown.** The probe is wired and logs to the Web Inspector console; the verification step decides whether to keep this path or fall back to a different counter design.
- **`engine-rs` is statically linked into Mane.** `crate-type = ["rlib", "staticlib"]`. The `libmane_engine.a` content is absorbed at link time; the .app has no external `libmane_engine` dependency. Mane.debug.dylib grew from ~600KB to ~6.4MB to account for adblock-rust.
- **`.glassEffect()` is in the macOS 26.2 SDK.** Cards apply it guarded by `#available(macOS 26.0, *)` with `.regularMaterial` fallback (`glassBackground` helper in `Views/Card.swift`).
- **`project.pbxproj` was hand-edited heavily this session.** All edits were narrow string replacements with surrounding context; the build verified clean at each step. Watch for collisions on the next Xcode-touched edit.

# Reference: visual direction and detailed implementation order

The sections below are the design doc that drives the To do list above. Treat them as load-bearing detail, not commentary.

## Visual direction

Look and feel: analytics dashboard, not System Settings panel. Reference is the standard SEO-dashboard layout — a strip of KPI tiles across the top, then larger chart cards below. Liquid Glass material on every card (real `.glassEffect()` where the macOS 26 SDK exposes it, `.thickMaterial` / `.regularMaterial` as fallback). SF Pro throughout, large `.title` numbers in KPI tiles, `.caption` deltas in green/red.

Approximate layout:

```
┌──────────────────────────────────────────────────────────────┐
│  Mane                                          [ Past 7d ▾ ] │
├──────────────────────────────────────────────────────────────┤
│  [Blocked] [Today] [Rules active] [Sites] [Trackers]         │
│  ┌─Blocks over time────────┐ ┌─Top blocked domains──┐        │
│  │ filled gradient area    │ │ horizontal bar chart │        │
│  └─────────────────────────┘ └──────────────────────┘        │
│  ┌─By category─────────────┐ ┌─Filter lists─────────┐        │
│  │ bar chart               │ │ EasyList    · 2d ago │        │
│  │ Ads · Trackers · Social │ │ EasyPrivacy · 2d ago │        │
│  └─────────────────────────┘ │ [ Update now ]       │        │
│                              └──────────────────────┘        │
└──────────────────────────────────────────────────────────────┘
```

Charts use SwiftUI Charts (built-in, `import Charts`). No third-party chart library.

## Implementation order

### 1. Strip the converter shell

Delete:
- `mac-app/Mane/Mane/Base.lproj/Main.storyboard`
- `mac-app/Mane/Mane/ViewController.swift`
- Any `Main.html` / `Main.css` / `Main.js` web-view resources the converter dropped in (under `mac-app/Mane/Mane/Resources/`).

Convert `mac-app/Mane/Mane/AppDelegate.swift` from a Cocoa `@main class AppDelegate` into:

```swift
import SwiftUI

@main
struct ManeApp: App {
    var body: some Scene {
        WindowGroup("Mane") {
            DashboardView()
        }
        .windowResizability(.contentSize)
    }
}
```

Update `mac-app/Mane/Mane/Info.plist`:
- Remove `NSMainStoryboardFile` key.
- Make sure `LSUIElement` is **not** set (we want a dock icon and a normal window).

Update `mac-app/Mane/Mane.xcodeproj/project.pbxproj` to drop the storyboard and ViewController file references from the `Mane` target. If pbxproj edits break the build, the fallback is: open the project in Xcode, remove the references from the Project Navigator, ensure `AppDelegate.swift` is the only `@main` entry.

### 2. Link `engine-swift` as a local Swift package

Add `../../engine-swift` as a local package dependency on the `Mane` target. In `project.pbxproj` this means a new `XCLocalSwiftPackageReference` block plus a `PBXBuildFile` referencing the `ManeEngine` product on the Mane target's frameworks build phase.

If that pbxproj edit is hairy, the Xcode UI path is: File → Add Package Dependencies → Add Local → choose `engine-swift/` → add `ManeEngine` to the `Mane` target.

Confirm by importing `ManeEngine` in a new Swift file and building. The Rust dylib it links against is already built by `./scripts/build-swift-bridge.sh` and lives at `target/release/libmane_engine.dylib`.

### 3. Stats persistence in the extension

In `safari-ext/background.js`:
- Keep the existing `onRuleMatchedDebug` listener (no-op on Safari but free on Chrome).
- Add a fallback poll: on `chrome.webNavigation.onCompleted`, call `chrome.declarativeNetRequest.getMatchedRules({})` and diff against the previous count. Increment per-domain aggregates.
- Persist aggregates to `chrome.storage.local` under the key `mane.stats.v1`, shape:

```json
{
  "version": 1,
  "days": {
    "2026-05-18": { "total": 483, "byDomain": { "doubleclick.net": 91, "...": "..." } }
  }
}
```

- Add a `runtime.onMessageExternal` (or `runtime.onMessage` if the native handler dispatches through `runtime.sendMessage`) listener that returns the stats blob when asked.

In `mac-app/Mane/Mane Extension/SafariWebExtensionHandler.swift`:
- Override `messageReceived(with:)` to accept a `{ "type": "getStats" }` payload from the container app, forward it to the extension's JS side via `SFSafariExtensionRequest`, and reply with the stats blob.
- Likely needs a paired `messageReceivedFromContainingApp` if Apple's API surface in macOS 26 splits the two directions.

Caveat: `chrome.declarativeNetRequest.getMatchedRules()` requires the `declarativeNetRequestFeedback` permission, which we already have in `manifest.json`. On Safari it may still return empty for static rulesets. If it does, the only fallback is to ask the browser to instead use a dynamic ruleset (which can be observed) for a small subset of high-traffic domains, or to accept that the daily counter is approximate. Investigate this first before building the full UI, because if neither works the Activity tile has to be redesigned.

### 4. `DashboardModel: ObservableObject`

New file `mac-app/Mane/Mane/DashboardModel.swift`:

```swift
@MainActor
final class DashboardModel: ObservableObject {
    @Published var isReady = false
    @Published var ruleCount: Int = 0
    @Published var filterLists: [FilterListInfo] = []
    @Published var todayBlocks: Int = 0
    @Published var totalBlocks: Int = 0
    @Published var timeSeries: [DayStat] = []
    @Published var topDomains: [DomainStat] = []
    @Published var byCategory: [CategoryStat] = []

    private let engine: ManeEngine
    private var pollTimer: Timer?
    // ...
}
```

The model:
- Initialises `ManeEngine` from the bundled filter lists.
- Reads filter list freshness from a small `filterlists-meta.json` we embed in the app bundle at build time (the App Sandbox would block direct reads from outside the bundle).
- Polls extension stats every 30s via `SFSafariApplication.dispatchMessage(withName:toExtensionWithIdentifier:userInfo:completionHandler:)`.

### 5. Views

New files under `mac-app/Mane/Mane/Views/`:
- `Card.swift` — reusable container, rounded rect with material background and inset content.
- `KPITile.swift` — title, big number, delta, "vs previous N days" caption.
- `BlocksOverTimeChart.swift` — `Chart { AreaMark(x: .value(...), y: .value(...)) }` with linear gradient fill.
- `TopDomainsChart.swift` — horizontal `BarMark` chart, top 8 domains.
- `CategoryChart.swift` — vertical `BarMark` chart, three to five categories.
- `FilterListsCard.swift` — list of `FilterListInfo`, last-updated relative time, "Update now" button.
- `DashboardView.swift` — composes everything, owns the `@StateObject var model = DashboardModel()`.

Default window size around 980×720, minimum 760×560.

### 6. Liquid Glass polish

- Window: `.containerBackground(.thickMaterial, for: .window)` on `DashboardView`.
- Cards: `.glassEffect()` if available in the SDK at compile time (guard with `#available(macOS 26, *)`), otherwise `.background(.regularMaterial, in: .rect(cornerRadius: 16))`.
- Use `Color.accentColor` sparingly for the delta arrows and the primary button. Everything else neutral.
- Type hierarchy: card titles `.subheadline.weight(.medium)`, KPI numbers `.system(size: 32, weight: .semibold, design: .rounded)`, captions `.caption.foregroundStyle(.secondary)`.
- Spacing scale: 8 / 12 / 16 / 24. No magic numbers.

### 7. Build, launch, verify

```sh
xcodebuild -project mac-app/Mane/Mane.xcodeproj -scheme Mane build
```

Then run from Xcode and verify:
1. The Mane window opens directly into the dashboard, not the converter's "enable in Safari" page.
2. Engine card shows `116,944 rules loaded` (or the current build number) and the filter list freshness in days.
3. Safari extension still blocks ads on theguardian.com (sanity check — the dashboard work shouldn't have regressed the ruleset).
4. After visiting a few ad-heavy pages, the KPI tiles start showing non-zero values within 30 seconds of returning to the dashboard.
5. Charts render with real (or freshly populated) data.
